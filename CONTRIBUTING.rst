Contributing to Froststrap
==========================

Thank you for showing interest in contributing to Froststrap!

Building Froststrap
~~~~~~~~~~~~~~~~~~~

An updated copy can be found online at https://docs.froststrap.xyz/docs/contributing/build-from-source

Accepted contributions
~~~~~~~~~~~~~~~~~~~~~~

Rather listing everything we want to allow, its easier to say we do have a list of stuff which is considered
going to be attributed as a contribution.


- No fully AI changes- those with no human in the loop
- Singular changes like changing a return of something that is type ``()`` to actually implicitly return type ``()`` - simply put, removing a ``;`` when it's the last line in a function


Things needed to do a contribution (PR/MR)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Checks:

- Spell checking (``typos`` cli tool can be useful)
- Code legal/licensing (``reuse`` cli tool can be useful) 
- Code formatting (``cargo fmt``, ``nix fmt``, and ``dotnet format``)

Make sure anything you add tries to not impede on anything else:
- Warnings
- Errors
- Other features from being implemented (e.g a rewrite of something whilst it's trying to get simply a new feature)


Things nedeed to do a contribution (issues)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

When creating a issue, you have to accept the following

- The ticking of information on a Issue must be correct otherwise depending on how we feel, we might put a punishment out on you, like a block
- No repeating issues, even if say X release fixes issue Y, but you find issue Y on release Z, you need to make a request to open back up issue Y instead.
- Sometimes it's better to have discourse- so theres other methods to make sure to make an issue like our Discord server
